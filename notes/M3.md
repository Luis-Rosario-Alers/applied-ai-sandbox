# User Authentication Implementation Plan

## Context

The sandbox Flask app currently has:
- In-memory note storage (`app.notes` list of dictionaries)
- Form validation (Task 01) and delete functionality (Task 02) in place
- No authentication, database, or user concept
- Minimal test infrastructure using pytest fixtures

This plan adds user authentication so that users can register, log in, see only their own notes, and log out.

## Design Decisions

### 1. Database & Models
- **Add Flask-SQLAlchemy** for SQLite database management (cleaner than raw sqlite3)
- **Create `models.py`** with User model only (notes remain in-memory for backward compatibility)
- **User table schema:**
  - `id` (Integer, primary key)
  - `username` (String, unique, required)
  - `password_hash` (String, required)
  - Methods: `set_password()`, `check_password()`

### 2. Notes Association
- Add optional `user_id` field to note dictionaries (backward compatible)
- Filter notes by `current_user.id` when displaying home page
- Existing tests remain compatible because they work with unfiltered `app.notes`

### 3. Flask-Login Integration
- Initialize `LoginManager` in `create_app()`
- Wire up `@login_manager.user_loader` callback
- Apply `@login_required` decorator to protected routes: `/`, `/notes/new`, `/notes/<idx>/delete`
- Redirect unauthenticated users to `/login` automatically

### 4. Routes
New routes:
- `GET /login` → render login form
- `POST /login` → validate credentials, establish session
- `GET /register` → render registration form
- `POST /register` → create user account, log in
- `POST /logout` → clear session, redirect to login

Modified routes:
- `GET /` → require login, filter notes by `current_user.id`
- `GET/POST /notes/new` → require login, attach `user_id` to new notes
- `POST /notes/<idx>/delete` → require login, check user ownership

### 5. Templates
- Create `base.html` with navigation (logged-in user name, logout button)
- Create `login.html` with username/password form
- Create `register.html` with username/password/confirm form
- Update `home.html` and `new_note.html` to extend `base.html`

## Critical Implementation Details

### In app.py
- Set `SQLALCHEMY_DATABASE_URI` to `sqlite:///sandbox.db` (or `:memory:` in tests)
- Call `db.create_all()` on app startup to create tables
- User loader: `User.query.get(int(user_id))`
- Login form validation: check username exists AND password matches
- Register form validation: username required (3+ chars, unique), password required (6+ chars), confirm match
- Home page filter: `[n for n in app.notes if n.get("user_id") == current_user.id]`
- New note: add `"user_id": current_user.id` to note dict
- Delete: check `note.get("user_id") == current_user.id` before allowing deletion

### In tests/conftest.py
- Use `:memory:` SQLite DB for tests (no file I/O)
- Create `authenticated_client` fixture that logs in a test user
- Update `app` fixture to initialize database and clean up after tests
- Helper: seed notes with `user_id` for backward-compatible tests

### In models.py
```python
from werkzeug.security import generate_password_hash, check_password_hash
from flask_login import UserMixin

class User(db.Model, UserMixin):
    id = db.Column(db.Integer, primary_key=True)
    username = db.Column(db.String(80), unique=True, nullable=False)
    password_hash = db.Column(db.String(200), nullable=False)
    
    def set_password(self, password):
        self.password_hash = generate_password_hash(password)
    
    def check_password(self, password):
        return check_password_hash(self.password_hash, password)
```
